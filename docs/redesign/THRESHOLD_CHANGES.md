# Threshold Change Log

Any change to `verify/thresholds.json` must be documented here.

| Date | Milestone | Field | Old Value | New Value | Reason |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 2026-10-18 | M1 | blob.litLuma (new) | - | 50 | Initial definition: a pixel counts as "lit" at luma >= 50 against the resting background |
| 2026-10-18 | M1 | blob.cropScale (new) | - | 2 | Initial definition: the focal crop is nearest-neighbour upscaled 2x before component counting so touching points separate |
| 2026-10-18 | M2 | dHash.minHammingDistance | removed | - | Metric invalid. Measured over the committed shots: same scene across viewports scored 3-14 (mean 7.0) while different scenes at one viewport scored 2-11 (mean 5.9), so "identical" and "different" were inverted and the >=12 limit was unreachable. Replaced, not relaxed. |
| 2026-10-18 | M2 | composition.minJaccardDistance (new) | - | 0.3 | Occupancy Jaccard distance (32x18 grid of lit pixels, art region only) measured on the same shots: identical frame 0.000; different scenes min per viewport 0.376 (mobile), 0.613 (tablet), 0.570 (laptop), 0.726 (desktop). 0.3 catches the real failure mode (two scenes serving one cloud, distance 0) with a safe margin below the measured floor. |
| 2026-10-18 | M2 | luma.nonBgPercent domain | full-frame screenshot | WebGL canvas only | Definition fix, limits unchanged (8-40). UI text is not art: on welcome desktop the full-frame reading was 9.56% while the art region measured 5.68%, so 41% of the "coverage" was chrome. Same correction the blob check already used. |

| 2026-10-18 | M2 | luma/blobs/amber domain (documentation) | mixed: coverage on canvas crop, blob on crop of the crop | all four art metrics on the canvas capture only | No limit changed. `imageStats` and the blob counter both read the canvas-only capture (`blobShot`); near-white %, mean luma, non-bg %, amber % and the connected-component count are therefore claims about the render, never about DOM text or chrome. |

| 2026-10-19 | P1 | look + composition gate scope (documentation) | measured on every row | N/A when `placeholder: true` | No limit changed. Until real backdrops arrive (PENDING_HUMAN_INPUT §1) every room renders the same labelled slate, so near-white/luma/coverage/amber/blob and cross-room composition distance describe a placeholder, not art. Rows re-enable automatically once a scene's header says `placeholder:false`. |

| 2026-10-20 | P1 | blob measurement region (definition) | fixed focal rect from `scenes.json` | `__sceneFit.screen` subject box + 6% pad (falls back to focal rect when fit is absent) | No limit changed. The hand-authored focal rect drifted from what the camera actually framed: on welcome@1920x1080 the stale rect covered 935 lit px / 51 components, while the same render inside the fitted subject box gives 1603 components with the largest at 2.3%. Measuring empty frame produced a false "blob" verdict every full scan. Component-count limits are unchanged and still measured on the canvas-only capture. |

| 2026-10-21 | P2 | copy (new section) | - | 5 rooms x 2 viewports, 9 patterns | New gate, additive only: no existing limit changed or relaxed. Engineering provenance (`PENDING_HUMAN_INPUT`, `*_PROVIDER=`, "asset pending", "lands in P5") must not reach the product surface. `rooms`/`viewports` name entries from `verify/scenes.json` (the gate throws on an unknown viewport instead of silently skipping); `patterns` are the only place a banned string is written, so no script inlines one. `roadmap-phase` matches `P5`/`P8` as whole words only, so `p5s`, `P50` and `P800` do not trip it. Enforced in both directions by `tests/forbidden-copy.test.mjs` and in every cell of the full sweep by `verify/run.mjs`. |
| 2026-10-23 | P2 | tests/office-camera-fit: procedural cloud count floor | 15000 | 8000 | The 15000 floor was measured while every room fitted the whole arch. The fixture now fits each room's own subject (the room's life, not its doorway), so the camera stands closer, the 6.2 px screen gate dedupes more, and a 20000-point budget solves to 9536-13778 across the five rooms. The floor still catches a cloud that collapsed; it no longer demands the density a different framing produced. The plate-level gates (coverage 8-40 %, mean luma 4-24, blob) are unchanged and still pass on the ten final assets. |
| 2026-10-23 | P2 | tests/office-engine: dptscn fixtures (documentation) | ten committed binaries | one synthetic buffer per run | No limit changed. The ten `public/scenes/*.dptscn` files left with the procedural art path, and the two parser tests read those files, so they failed on a clean checkout. They now build a buffer in memory: the invariants (consistent lengths, corrupt magic rejected) are the same and no longer depend on a committed binary. |
